# Nautikos — экологический мониторинг Каспия

[Рабочая версия](https://nautikos-caspian.vercel.app) · [GitHub](https://github.com/projectedvc/nautikos-caspian)

Nautikos — геопространственная платформа для сравнения реальных спутниковых наблюдений Каспийского моря за 2020–2026 годы. Пользователь выбирает один год или включает шторку для сравнения двух лет, приближает любой участок побережья и применяет один из шести воспроизводимых экологических продуктов. Обычная работа карты не обращается к Copernicus: расчёты один раз архивируются на сервере Jupyter в геопривязанные Cloud Optimized GeoTIFF, а интерфейс получает только локальные XYZ-тайлы.

Платформа решает задачу первичного экологического скрининга. Она помогает определить участок, который требует повторного пролёта, проверки ветра и судовой активности или выезда полевой группы. Спутниковый сигнал не заменяет лабораторный анализ и не является единственным доказательством загрязнения.

## Возможности MVP

- выбор любого года с 2020 по 2026;
- режим одного года и сравнение двух разных лет интерактивной шторкой;
- панорамный вид всего Каспия и детальные тайлы при приближении;
- три продукта Sentinel-2 для суши, рек и береговой зоны;
- один радиолокационный продукт Sentinel-1 для кандидатов поверхностной плёнки;
- температура поверхности воды Sentinel-3 SLSTR;
- цвет воды и взвешенное вещество Sentinel-3 OLCI;
- фиксированные шкалы цветов, одинаковые для всех тайлов и лет;
- выделение области, расчёт площади, статистика и экспорт снимка;
- режим решений и AI-пояснение для выбранного участка;
- светлая и тёмная темы.

## Шесть спутниковых продуктов

| Интерфейс | Product ID | Источник | Расчёт и назначение | Нативная детализация |
|---|---|---|---|---:|
| Реки и водотоки | `rivers` | Sentinel-2 MSI L2A | NDWI `(B03-B08)/(B03+B08)`; красным выделяется наблюдаемая открытая вода, включая различимые водотоки и устья | 10 м |
| Водная граница и изменение берега | `water_extent` | Sentinel-2 MSI L2A | годовая NDWI-маска воды; шторка показывает наблюдаемое отступление или наступление воды | 10 м |
| Растительность прибрежного буфера | `coastal_vegetation` | Sentinel-2 MSI L2A | NDVI `(B08-B04)/(B08+B04)` после исключения открытой воды | 10 м |
| Кандидаты поверхностной плёнки | `oil_candidates` | Sentinel-1 IW GRD, VV | отклонение обратного рассеяния от локального SAR-фона над водой | около 20 м |
| Температура поверхности воды | `water_temperature` | Sentinel-3 SLSTR L2 WST | июльская температура водной поверхности, °C | 1 км |
| Цвет воды и взвесь | `water_colour` | Sentinel-3 OLCI L2 WATER, `TSM_NN` | крупномасштабный сигнал общего взвешенного вещества, `log10(g/m³)` | 300 м |

## Сопоставимость 2020–2026

- Для каждого года используется одинаковое окно: 1–31 июля.
- Sentinel-2 берётся из L2A, потому что официальная quarterly mosaic не покрывает весь диапазон 2020–2026.
- Облачность, тени и снег исключаются по SCL; в расчётах учитывается гармонизация Sentinel-2 Processing Baseline.
- Sentinel-1 сравнивается в одном режиме IW GRD и одной поляризации VV; маска воды берётся из того же июльского Sentinel-2 продукта.
- Все COG строятся на общей сетке `EPSG:3857` для Каспия `46.0,36.0,55.8,47.4`.
- Значения не растягиваются отдельно для каждого тайла. Диапазоны и палитры фиксированы, поэтому на границах тайлов нет скачков цвета.
- При изменении масштаба используется тот же годовой COG. Сцена или спутник не подменяются.

## Архитектура данных

```text
Copernicus Data Space / официальный STAC
        │ однократная архивная подготовка
        ▼
Jupyter: /home/jovyan/work/caspiansea/data-v2
        ├── cog/{product}/{year}.tif
        ├── manifests/{product}/{year}.json
        └── tiles-local-v1/... (версионированный кэш)
        │
        ▼
FastAPI: /v2/tiles/{product}/{year}/{z}/{x}/{y}.png
        │
        ▼
Vercel / MapLibre: два синхронных XYZ-слоя и шторка
```

В интерфейсе нет аналитических `ImageOverlay`, статических прямоугольных WebP и runtime-fallback в Copernicus. Если локальный COG или его manifest отсутствует, сервер возвращает явную ошибку и не рисует синтетическую замену.

## Локальный контракт schema 3

```text
$NAUTIKOS_DATA_ROOT/
  cog/{product}/{year}.tif
  manifests/{product}/{year}.json
```

Manifest содержит `schema: 3`, точные `product`, `year`, `source`, список `acquisition_ids`, относительный путь `asset`, период, CRS, сетку, алгоритм и SHA-256. Файлы с признаками `synthetic` или `fallback` отклоняются. COG должен быть tiled GeoTIFF с геопривязкой и внутренними overviews.

Доступность и тайлы:

```text
GET /v3/manifest
GET /v2/manifest
GET /v2/tiles/{product}/{year}/{z}/{x}/{y}.png
POST /v2/aoi/statistics
POST /v2/aoi/export
```

## Построение локального архива

OAuth-данные Copernicus используются только сборщиком на Jupyter:

```env
CDSE_CLIENT_ID=...
CDSE_CLIENT_SECRET=...
```

Проверка без сети и записи:

```bash
python server/scripts/build_cog_products.py \
  --years 2020:2026 --products all \
  --data-root /home/jovyan/work/caspiansea/data-v2 \
  --dry-run
```

Resume-safe сборка:

```bash
python server/scripts/build_cog_products.py \
  --years 2020:2026 --products all \
  --data-root /home/jovyan/work/caspiansea/data-v2 \
  --workers 2 --continue-on-error
```

`water_temperature` принимает только настоящие геопривязанные SLSTR L2 WST-растры через `data-v2/inputs/water_temperature/{year}/manifest.json`. Подмена температурой воздуха или SLSTR L1B запрещена. Повторный запуск пропускает COG только после проверки manifest, контрольной суммы, сетки и внутренних overviews.

## Быстрый запуск

Требования: Node.js 22+, Python 3.11+.

```bash
git clone https://github.com/projectedvc/nautikos-caspian.git
cd nautikos-caspian
npm ci
python -m venv server/.venv
server/.venv/bin/pip install -r server/requirements.txt
cp .env.example .env.local
```

Интерфейс:

```bash
npm run dev
```

Jupyter data API:

```bash
export NAUTIKOS_DATA_ROOT=/home/jovyan/work/caspiansea/data-v2
server/.venv/bin/python -m uvicorn server.nautikos_server.api:app \
  --host 0.0.0.0 --port 8787 --workers 1
```

Полный серверный bootstrap:

```bash
bash server/scripts/start_jupyter_pipeline.sh
```

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `NEXT_PUBLIC_NAUTIKOS_DATA_URL` | публичный HTTPS-адрес Jupyter imagery API, используемый браузером |
| `NAUTIKOS_DATA_BACKEND` | серверный адрес Jupyter API для AI/AOI и проверки manifest |
| `NAUTIKOS_DATA_ROOT` | каталог локальных COG и manifest-файлов на Jupyter |
| `NAUTIKOS_ALLOWED_ORIGINS` | разрешённые origins для FastAPI |
| `CDSE_CLIENT_ID`, `CDSE_CLIENT_SECRET` | только однократная архивная сборка; в Vercel не требуются |

Секреты не коммитятся и не передаются в клиентский код.

## Проверка

```bash
npm test
python -m unittest discover -s server/tests -p "test_*.py" -v
python server/scripts/build_cog_products.py --dry-run --years 2020 --products all
```

Перед демонстрацией проверяются:

1. все 42 пары `6 продуктов × 7 лет` доступны в `/v3/manifest`;
2. 2020 и 2026 имеют разные `acquisition_ids` и SHA-256;
3. шторка меняет оба года независимо;
4. один и тот же слой остаётся геометрически совмещённым при отдалении и приближении;
5. в соседних тайлах нет прямоугольных дыр и разной цветовой шкалы;
6. режим выделения области не включается сам и экспорт использует ту же фиксированную палитру, что карта.

## Научные ограничения

- NDWI показывает наблюдаемую открытую воду, а не официальную речную сеть и не глубину.
- Изменение береговой линии не устанавливает причину: уровень моря, влажный грунт, лёд, волны и смешанные пиксели требуют проверки.
- NDVI не определяет вид растения или причину стресса.
- Тёмная SAR-аномалия является кандидатом поверхностной плёнки. Аналогичный сигнал создают штиль, дождь, биогенная плёнка и ветровая тень; нужны ветер, AIS, повторный пролёт и полевая проба.
- SLSTR измеряет skin temperature поверхности с шагом около 1 км, а не температуру всей толщи воды.
- `TSM_NN` показывает взвешенное вещество и изменение цвета воды, но не химический состав отхода и не его токсичность.

## Развитие

- объединение SAR-кандидатов с ветром, течениями и AIS;
- автоматический выбор маршрута отбора проб;
- сегментационная модель, возвращающая географическую маску, а не случайные точки;
- уведомления о новых устойчивых аномалиях;
- интеграция с дронами, буями и лабораторными измерениями;
- общий кабинет экологических служб прикаспийских государств.

Технологии: Next.js, React, TypeScript, MapLibre GL, FastAPI, Rasterio, COG и Copernicus Sentinel-1/2/3. При публикации результатов сохраняется атрибуция Copernicus/ESA и явно указывается необходимость полевой верификации.
